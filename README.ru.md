# Система Спауна и Сервисы

## Описание  
Эта часть проекта реализует надежную и гибкую систему спауна сущностей, используя паттерны проектирования, такие как **Object Pooling**, **Factory** и **Service Locator**

---
## Основные Компоненты

### 1. EntitySpawnFactory (Фабричный паттерн)  
Класс `EntitySpawnFactory` централизует процесс создания и спауна сущностей. Он упрощает управление различными типами объектов.

#### Преимущества:
- Отделение логики создания сущностей повышает читаемость и удобство сопровождения.
- Добавление новых типов сущностей не требует изменения кода фабрики.

### 2. CustomPool (Паттерн Объектный пул)  
`CustomPool` реализует объектный пул, который значительно повышает производительность, повторно используя объекты вместо постоянного создания и удаления. Это снижает нагрузку на память и сборщик мусора.

#### Преимущества:
- Избегает частых выделений памяти и работы сборщика мусора.
- Автоматически масштабируется, создавая новые объекты только при необходимости.

### 3. IAssetProvider (Паттерн Внедрения Зависимостей)  
Класс `AssetProvider` инкапсулирует логику загрузки и создания префабов, централизуя управление ресурсами.

#### Преимущества:
- Управление ресурсами отделено от игровой логики.
- Упрощает тестирование и расширяемость.

### 4. Система Сервисов (Паттерн Service Locator)  
Класс `AllServices` реализует паттерн **Service Locator**, обеспечивая централизованный доступ к игровым сервисам. Это позволяет легко получать зарегистрированные сервисы без жесткой привязки логики игры к конкретным реализациям. Если необходимо могу переделать реализацию на Zenject

#### Преимущества:
- Легко добавлять новые сервисы без изменения существующего кода.
- Централизованное управление состоянием сервисов снижает связанность компонентов.

---
## Примеры использования

### Регистрация сервиса  
```csharp
AllServices.Container.RegisterSingle<IMyService>(new MyService());
```

### Получение сервиса  
```csharp
var myService = AllServices.Container.Single<IMyService>();
```

### Спавн сущностей  
```csharp
var entity = entitySpawnFactory.SpawnDefaultEntity();
```

### Использование объектного пула  
```csharp
var entity = defaultEntityPool.Get();
```

# Система UI

## Обзор  
Этот проект реализует **модульную и масштабируемую систему UI в Unity**, используя **событийно-ориентированную архитектуру** и **внедрение зависимостей (DI)** для управления окнами и взаимодействиями.

## Основные особенности  
- **Регистрация и управление окнами:** окна динамически регистрируются и управляются через `WindowController`.
- **Layered UI:** разделение интерфейса на уровни (`HUD`, `Popup`, `Overlay`, `FullScreen`) для повышения производительности.
- **Модульная система окон:** каждое окно – это `UIElement`, который можно настраивать и управлять им отдельно.
- **Поддержка DI:** система использует **внедрение зависимостей** для управления сервисами и зависимостями.

## Компоненты

### 1. WindowRegistry  
- Хранит ссылки на зарегистрированные префабы окон и динамически управляет их обновлением.

### 2. WindowController  
- Управляет жизненным циклом UI-окон

### 3. UIRoot  
- Управляет различными слоями UI (`HUD`, `Popup`, `Overlay`, `FullScreen`).

### 4. UIElement  
- Базовый класс для всех UI-окон, отвечающий за анимации и переключение видимости.

### 5. GameView  
- Пример окна UI, взаимодействующего с `WindowController`.

## Использование

### Настройка WindowRegistry  
1. Создайте `WindowRegistry` в Unity.  
2. Добавьте префабы окон в список `windowPrefabs` через кнопку внутри ScriptableObject


### Управление слоями UI  
```csharp
UIRoot.GetLayer(UILayer.Popup);
```

### Открытие и закрытие окон  
```csharp
WindowController.OpenWindow<T>();
WindowController.CloseWindow<T>();
```

# Система Камеры

## Обзор  
Этот проект включает систему управления камерой для 3D-игры, поддерживающую **горизонтальное перемещение** с помощью **перетаскивания** и **следования за игроком**. Система использует **паттерн Стратегия** для динамического переключения между методами перемещения.

---
## Основные Компоненты

### 1. CameraObjectsData  
- Хранит ссылки на основные объекты камеры (`camera`, `holder`, `rotation`, `tracking plane`).

### 2. HorizontalCameraMovementStrategy  
- Управляет переключением между режимами **перетаскивания** и **следования за игроком**.

### 3. FollowPlayerBehaviour  
- Отвечает за **плавное следование камеры** за игроком.

### 4. MoveByDragBehaviour  
- Реализует **управление камерой с помощью перетаскивания**, учитывая инерцию и границы карты.

### 5. MapLimitsForCameraData  
- Определяет **границы движения камеры** и параметры **плавного возврата**.

![Camera Limits](https://raw.githubusercontent.com/nerfmee/Spawn/main/Assets/ContentForReadMe/CameraLimits.gif)

## Пример использования  
```csharp
var moveByDragBehaviour = new MoveByDragBehaviour(cameraObjectsData, dragMovementData, mapLimitsForCameraData, this);
moveByDragBehaviour.ProcessStartDrag(screenPosition);
moveByDragBehaviour.ProcessDrag(screenPosition);
moveByDragBehaviour.ProcessEndDrag();
```

# Система Управления Игроком

## Обзор  
Эта система управляет **перемещением игрока** и его **взаимодействием с окружением**, используя **модульные сервисы** Включает **событийную обработку ввода** и **физически корректное передвижение**.

## Основные Компоненты

### 1. Player Component  
- Отвечает за **движение** и **прыжки** игрока.
- Использует `InputService` для **событийной обработки ввода**.
- Опирается на `MovementService` для **физического управления движением**.

### 2. MovementService  
- Реализует `IMovementService` для управления движением.
- Использует `Rigidbody.velocity` для **плавного движения**.
- Обеспечивает **реалистичные прыжки**, используя `Physics.Raycast` для **определения земли**.

### 3. InputService  
- Реализует `IInputService` для **обработки пользовательского ввода**.
- Использует **событийную архитектуру** с событиями `OnMove` и `OnJump`.
- Управляет жизненным циклом ввода и поддерживает **переназначение управления**.
